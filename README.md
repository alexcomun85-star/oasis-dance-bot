# Бот шоу-балета Oasis Dance — @oasisdance_show_bot

Telegram-бот для приёма заявок на выступления шоу-балета Oasis Dance. Работает на VPS (служба systemd),
данные хранит в SQLite (`data/bot.db`), ИИ-ассистент — Google Gemini.

## Для клиентов
- **Заявка за минуту** — 6 шагов: тип мероприятия (кнопки), дата (календарь), место, программа,
  телефон одной кнопкой «Отправить номер» (или «лучше написать в Telegram»), пожелания.
- **«Перезвоните мне»** — оставить номер одной кнопкой.
- **Вопросы** — любой текст отвечает ИИ-ассистент по базе знаний `knowledge.md`.
- Видео и фото (ВКонтакте, канал, Instagram), контакты, сотрудничество.
- `/privacy` — обработка персональных данных, `/forget` — удалить свои данные.
- Меню команд и описание профиля бот настраивает сам при запуске.

## Для администратора (кабинет заявок)
- Новая заявка приходит карточкой с кнопками: **Взять в работу**, **Выполнена**, **Отклонить**,
  **Написать клиенту**. Статус обновляется у всех администраторов.
- **Написать клиенту** — сообщение уходит клиенту от имени шоу-балета; клиент отвечает кнопкой
  «Ответить менеджеру», ответ приходит администраторам.
- **Брошенные заявки** — если клиент начал анкету и не закончил за 30 минут, приходит уведомление
  с тем, что он успел заполнить.
- **Пост в канал** (`/post` или кнопка в кабинете): пришлите текст, фото или видео с подписью — или
  нажмите «Написать с ИИ» и укажите тему. Бот покажет превью, по кнопке опубликует в канал
  (с кнопкой «Заказать выступление», ведущей в бота, — её можно отключить) и предложит закрепить пост.
  Переходы из канала видны в статистике. Бот должен быть администратором канала с правом публикации.
- **Соцсети → канал** (`/sources`): бот каждые 20 минут проверяет страницы ВКонтакте из `VK_SOURCES`.
  Новую публикацию ИИ переписывает для Telegram (факты и все ссылки сохраняются, ссылка на оригинал
  добавляется), фото переносится. Черновик приходит администратору: «Опубликовать», «Другой вариант»,
  «Пропустить»; опубликованный пост можно удалить из канала кнопкой. При `AUTO_PUBLISH=1` посты выходят
  сразу. При первом подключении старые публикации не переносятся — по кнопке можно взять 3 последние.
  Любой пост, **пересланный боту** администратором (например, из Telegram), тоже превращается в черновик.
  **Ленты без ключей** (`FEED_SOURCES`): RSS/Atom любого сервиса (rss.app, vkrss.com и т.п.) или JSON.
  Instagram @oasis_dance_show подключён через `feeds/instagram.json` — файл раз в день обновляет задание
  по расписанию в Claude (сервис vidIQ). Посты из Instagram всегда идут на одобрение и получают пометку
  о Meta (`INSTAGRAM_NOTE`). Личные публикации ИИ отсеивает; служебную подпись с телефоном и @отметками убирает.
- Команды: `/admin` — кабинет (новые, в работе, закрытые), `/orders` — новые заявки, `/stats` — статистика, `/post` — пост в канал, `/sources` — соцсети → канал.
- Администраторы — числовые ID в `ADMIN_CHAT_IDS` (свой ID: команда `/myid`).

## Установка и обновление
Первая установка на сервере (Ubuntu/Debian), от root:
```
apt-get update && apt-get install -y git && git clone https://github.com/alexcomun85-star/oasis-dance-bot.git && cd oasis-dance-bot && bash install.sh
```
Обновление до новой версии:
```
cd ~/oasis-dance-bot && git pull && bash install.sh
```
`install.sh` копирует код в `/opt/oasis-bot`, ставит зависимости и перезапускает службу; файл `.env`
и данные в `data/` не трогает.

Перед запуском остановите другие копии бота (например, в Replit): две копии одновременно не работают (ошибка 409).

## Обслуживание
| Что сделать | Команда |
|---|---|
| Журнал в реальном времени | `journalctl -u oasis-bot -f` |
| Последние строки журнала | `journalctl -u oasis-bot -n 30 --no-pager` |
| Перезапустить | `systemctl restart oasis-bot` |
| Изменить настройки | `nano /opt/oasis-bot/.env`, затем перезапуск |
| Резервная копия данных | `cp /opt/oasis-bot/data/bot.db ~/bot-backup.db` |

Токен бота и ключ Gemini в журнал не попадают (заменяются на `***`), тексты сообщений клиентов тоже.

## Ключ ВКонтакте (для «Соцсети → канал»)
1. Откройте dev.vk.com, войдите и создайте приложение (тип — для сайта или standalone, название любое).
2. В настройках приложения скопируйте «Сервисный ключ доступа».
3. На сервере: `nano /opt/oasis-bot/.env`, впишите `VK_SERVICE_TOKEN=ключ`, при необходимости
   поправьте `VK_SOURCES`, сохраните и выполните `systemctl restart oasis-bot`.
Страница-источник должна быть открытой (записи видны всем).

## Настройки (`.env`)
См. `.env.example`: токен, `ADMIN_CHAT_IDS`, ключ и модель Gemini, контакты, лимиты ассистента
(`AI_LIMIT_PER_USER_HOUR`, `AI_LIMIT_PER_DAY`), `ABANDON_MINUTES`, `OPERATOR_NAME`.

## Проверка кода
```
python3 -I tests/sim.py
```
Прогоняет все сценарии (заявка, кабинет, переписка, брошенные заявки, ассистент, лимиты, защита) без сети.

## Файлы
| Файл | Назначение |
|---|---|
| `bot.py` | приём обновлений (параллельно по чатам), меню, ассистент, «Перезвоните мне», профиль бота |
| `order_form.py` | анкета заявки, календарь |
| `admin.py` | кабинет заявок, уведомления, переписка с клиентом, брошенные заявки |
| `storage.py` | база SQLite |
| `channel.py` | публикация постов в канал |
| `sources.py` | ВКонтакте и пересланные посты → черновики → канал |
| `ai.py`, `knowledge.md` | ассистент и его база знаний |
| `tg.py` | запросы к Telegram |
| `config.py` | настройки из `.env` |
